# Scripts

Reusable automation for operating this workspace, such as checks, conversion adapters, and build steps. The agent writes and runs these scripts; researchers never need to run or edit them.

Research analysis code is kept separately in `code/`, which is created only when a project needs it (`research-code-setup`), so that workspace tools cannot destabilize an analysis environment.

## Current scripts

Run `python scripts/check_readmes.py`; it exits with status 1 and lists the problems when a check fails. |

Run `python scripts/check_capabilities.py`. |

| [`credentials.py`](credentials.py) | Stores credentials in the ignored `.env.local` without showing them: `set` opens a one-time page on this computer for private entry, `status` shows only whether a name is set, `remove` deletes one value, and `run` passes values to another program. It refuses to store anything when Git could track `.env.local`. |

Its modules are in [`ingestion/`](ingestion/README.md). |
| [`literature.py`](literature.py) | Records scope-checked Sciverse searches, host-search results, and local passage retrieval; downloads public PDFs in resumable batches, records source-identity checks, and audits BibTeX links. It does not convert documents; use `ingest.py` for that. Its modules are in [`literature/`](literature/README.md). |
| [`research.py`](research.py) | Checks the form of the research records (decision records, feedback actions, ideas, venue notes, and result records) and reports results whose inputs or outputs changed since they were recorded (`check`); creates the research code folder with only the parts a project needs (`code-init`); runs research code and records the command, code checksum, interpreter, inputs, outputs, and logs in `code/runs/` (`run`); and lists recorded runs (`runs`). |
| [`manuscript.py`](manuscript.py) | Checks the manuscript against the workspace conventions (manifest, math, equation labels, figure, table, equation, and section references, citation keys against the bibliography, images, LaTeX commands left in the prose (which Pandoc drops from a Word file), hand-numbered references, half-width punctuation after Chinese or Japanese text, and `[TODO: ...]` markers); sets the ordered section list; assembles a preview with word counts; records checks with the checksums of their inputs and reports stale ones; and keeps major-revision baselines, applies a staged candidate with a resumable log, records a revision as completed or, when the baseline is restored, abandoned, and restores a baseline. |
| [`check_edit.py`](check_edit.py) | Compares a revised text with its original after a translation, a polish, a shortening, or a revision for natural prose. It lists the protected items that disappeared or appeared (front matter, code, math, labels, citation keys, cross-references, image and link targets, footnotes, open markers, headings, and numbers) and, within one language, the hedges, negations, and limiting words from [`check_edit.json`](check_edit.json) whose count changed. It changes nothing. |
| [`text_rules.py`](text_rules.py) and [`text_rules.json`](text_rules.json) | Shared, language-neutral boundary checks for citations, numbering, open markers, AI signatures, and English/CJK word counts. The data file extends detection vocabulary without selecting the manuscript language. |
| [`review.py`](review.py) | Checks the response and change records of review rounds (every item has its reviewer, source, comment, status, and response; addressed items link a done change in the same round), and reconciles a coauthor's edited Word file with the version sent and the current manuscript without changing anything. |
| [`export.py`](export.py) | Builds formatted outputs with an output profile: reports and installs the export tools (Pandoc, pandoc-crossref, mermaid-cli) with consent, creates profiles and their Word reference documents, builds and checks the DOCX (native equations formula by formula, figures and diagrams, references, citations, the title, authors, and keywords of the manuscript metadata, layout expectations, length, anonymization, open markers), renders a PDF with Word or LibreOffice for inspection, and freezes passing, current builds as releases that are never overwritten. Its filters are in [`export/`](export/README.md). |
| [`status.py`](status.py) | Summarizes where the research project stands, read from its records (library, ideas, plan, results, venues, outline, manuscript, checks, builds, releases, review rounds, revisions, feedback, unsaved work), and lists the gaps that suggest a next task, without changing anything. |
| [`versions.py`](versions.py) | Operates the workspace's Git history for the agent: read-only `inspect` and `scope`, `init` and `identity`, scoped `save` that refuses secrets and oversized files, `history` and `compare`, `retrieve` and `restore` (which keeps the current content first), `untrack`, a separate `practice` copy, `remotes`, and `backup`, which pushes only to a destination confirmed in `requirements/privacy.md` and checks the copy. |
| [`setup_mineru.py`](setup_mineru.py) | Installs MinerU into `.tools/mineru/` and its models into `.cache/mineru/`, and reports the installation, the models, and the free disk space. Run `install` and `models` only with the researcher's consent. |

Automated tests for these scripts are in [`tests/`](tests/README.md). Run them after changing a script.

## Conventions

The manuscript check reports explicit AI sign-offs and AI names in author metadata as problems; these prevent a Word build. The built DOCX is also checked for recognized signatures in paragraphs, including headers, footers, notes, and comments, and for AI names in creator properties. It allows ordinary discussion of AI products and disclosure prose. This limited text check supplements the standing instruction against AI signatures; findings require inspection and it does not recognize every possible form or language.

Research result freshness includes code checksums from linked run records, as well as the result's recorded inputs and outputs. `research.py check` prints existing `Used by` references when it finds stale evidence, or asks for dependency inspection when none are recorded. It reports unreadable or incomplete runs used as observed/checked results. It does not infer unrecorded claim relationships or validate scientific reasoning; the agent must inspect those. `research.py runs` also reports recorded code changes.

Tool discovery uses numeric release ordering in `.tools/`. The environment report and export route both prefer workspace Pandoc over PATH. Browser discovery accepts `PUPPETEER_EXECUTABLE_PATH`, uses Windows installation roots from the environment, and checks per-user macOS Applications as well as system Applications. Release pins and published archive digests remain deliberate reproducibility data.

- Prefer the Python standard library. When a script needs packages, use the project-local `.venv` and call its interpreter directly instead of relying on an activated shell.
- Scripts must work on Windows, macOS, and Linux, including paths with spaces and non-ASCII characters.
- Never print credentials or pass them as command arguments; redact them from logs.
- Reading and writing Markdown must never depend on a script.
