# Sciverse Literature Integration

Checked against OpenDataLab's public documentation on 2026-10-28. These are integration facts, not researcher consent, a credential, or proof that an account has access.

## Documented API

Sciverse documents a Bearer-token API at `https://api.sciverse.space`. The integrated `agentic-search` endpoint is `POST /agentic-search`; it accepts a natural-language query, optional `top_k` (1–100), `sub_queries` (0–4), and filters. The query limit is 4096 characters. Results may include snippets, `doc_id`, `chunk_id`, character offset, PDF page number, title, abstract, and metadata. Fields vary by account permissions, so callers must tolerate missing values. [Official agentic-search reference](https://sciverse.opendatalab.org.cn/docs/sciverse/api/agentic-search)

The structured `POST /meta-search` endpoint returns bibliographic metadata for title, DOI, and field-based searches; it does not return evidence passages. Its documentation directs clients to `meta-catalog` before building filters. [Official meta-search reference](https://sciverse.opendatalab.org.cn/docs/sciverse/api/meta-search)

The `GET /content` endpoint can retrieve source text by `doc_id`, `offset`, and `limit`. Offsets count Unicode characters; a source may have no readable full text. This adapter records the retrieved range separately from initial search snippets. [Official content reference](https://sciverse.opendatalab.org.cn/docs/sciverse/api/content)

The API documentation says HTTP 429 means an account quota/rate limit and recommends waiting instead of retrying; 500/502/503 may be retried with backoff. The adapter follows that distinction for Sciverse requests. [Official agentic-search reference](https://sciverse.opendatalab.org.cn/docs/sciverse/api/agentic-search)

The metadata adapter supports explicit filters, sorting, page numbers and opaque cursors. For filters and sorting it first retrieves `meta-catalog` and validates fields and filter operators against that account's catalog. Each request and returned pagination is recorded; `resume-sciverse-metadata` continues a recorded search one page at a time, preserving its query, filters, sorting, scope, prior results, and failed attempts. The `meta-paper-relations` adapter retrieves one requested page of citations, references, or related works for a `unique_id` in a recorded metadata result, with the original scope still active. Relationship records are discovery leads, not evidence of support. These extensions have synthetic tests only; their live behavior and account access remain unverified. [Catalog reference](https://sciverse.opendatalab.org.cn/docs/sciverse/api/meta-catalog), [relations reference](https://sciverse.opendatalab.org.cn/docs/sciverse/api/meta-paper-relations)

The resource adapter accepts only a safe relative path present in a recorded, authorized document context and stores a bounded, signature-checked image or PDF as a derived service resource. The experimental Paper Schema adapter uses an explicit opt-in flag, discovers a recorded metadata result by its DOI, and requests a bounded material pack only for a returned schema ID. It preserves the response, including truncation indicators. Identity and extracted claims still need verification against the source. Resource retrieval and these individual Paper Schema operations have synthetic tests only; they have not been validated live. Paper Schema is centered on AI conference papers. [Resource reference](https://sciverse.opendatalab.org.cn/docs/sciverse/api/resource), [Paper Schema reference](https://sciverse.opendatalab.org.cn/docs/sciverse/api/paper-schema)

## Privacy and account boundary

A Sciverse request sends the research query and any supplied identifiers to OpenDataLab. Before the first request in a workspace, the researcher must confirm which queries and identifiers may be sent. The exact confirmation and its scope belong in `requirements/privacy.md`; a machine marker lets `scripts/literature.py` refuse an unconfirmed request. The agent must still check that each query fits the human-readable scope.

The public docs say API keys are created through the account console and that a basic trial quota may be available, with actual access depending on account permissions. They do not establish this researcher's account access or a fixed price. Do not create an account, start a paid plan, or incur a charge without confirmation. Store a key only through `scripts/credentials.py` as `SCIVERSE_API_KEY`; requests are sent only to the fixed documented API host, and the key is not written to search records.

The API and overview pages reviewed here do not state how search queries are retained or whether they are used for training. This review did not establish a separate query-data policy. Do not claim that query retention or training use is off; disclose that these points are unknown when asking whether a query scope may be sent.

## Implementation boundary

`scripts/literature.py` records the provider, query, date, response fields, source identifiers, locators, and errors in `references/searches/`. A returned snippet remains labeled as a discovery snippet. The local search reads extracted Markdown without a vector database. Public PDF retrieval is a separate route; it does not use Sciverse downloads or the account's full-text endpoint to create an archived PDF.

Live service checks on 2026-10-28 used the explicitly authorized synthetic query `paper-template connectivity check` in an isolated temporary workspace. `agentic-search` returned three snippets with provider IDs and locator objects on two calls. `meta-search` returned 25 metadata records on one call. A `content` request for one ID returned 71 characters with a requested limit of 200. A separate retrieval smoke run made four `agentic-search` requests (one per public evaluation question, `top_k=5`, no retries); each returned five records. The expected climate-paper title appeared in the top five, while the expected Transformer paper and named clinical trials were not identified there by title or listed identifiers. No content was fetched or checked against originals. All temporary scopes, IDs, metadata, and text were removed after recording these outcomes; no project privacy scope was changed. These observations confirm the tested calls responded for the configured account, not that results are correct or complete. The [official overview](https://sciverse.opendatalab.org.cn/docs) says basic trial quota depends on account permissions; this run did not establish whether any request incurred a charge. Query retention or training use, repeat availability, quota behavior, and Windows/Codex operation remain unverified. Publisher/repository download access is outside the Sciverse checks.
