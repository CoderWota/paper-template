# Script Tests

Automated tests for the workspace scripts in [`scripts/`](../README.md). They use only the Python standard library and temporary folders whose paths contain spaces and non-ASCII characters, so the same tests can confirm behavior on Windows, macOS, and Linux.

The manuscript tests also cover AI signatures and author metadata, with ordinary AI discussion and disclosure as allowed cases. They verify that multilingual vocabulary stays in the data file rather than in Python rule code. Export tests cover signature refusal, final DOCX signatures split across runs in a header, AI creator properties, numeric tool release ordering, an explicit browser path, and Windows installation roots using simulated platform settings; these simulations do not verify operation on Windows.

Run them from the workspace root:

```text
python -m unittest discover -s scripts/tests -v
```

- `test_credentials.py` covers private credential entry through the one-time local page, the Git exclusion check, passing a value to another process, and the rule that no value is ever printed. It also covers that saving a second service keeps the first, that replacing one value keeps the others and every other line (comments, `export` lines, Windows line endings, a byte order mark), that ten processes saving at the same moment lose nothing, that a writer waits while another holds the file and gives up cleanly, and that a failed replacement keeps the old file and leaves no temporary file. All values are synthetic.
- `test_workspace_scripts.py` covers the README check, the skill copy script, and the environment report.
- `test_records.py` covers the availability table check and the writing rule check, including the drift each one exists to catch.
- `test_ingest.py` covers document import with the local route, using `fake_mineru_kit.py` in place of MinerU: archiving, duplicates, unsupported files, page coverage and the other checks, interruption and continuation, reuse and re-conversion, protection of hand edits, review rounds with Word comments, tracked changes, and PDF annotations, Markdown and text letters filed directly with no route and no parser, citation metadata, the README contract of every new folder, that a finished import leaves no temporary files, and that the parser's own output stays out of saved versions under the template's `.gitignore`.
- `test_ingest_cloud.py` covers the mineru.net route against a fake service on this computer: the refusal without a confirmed choice or a token, uploads that never carry the token, an expired token that stops the batch once, collecting unfinished work without a second upload, and a file that fails at the service. It cannot prove compatibility with the live service.
- `test_research.py` covers the research record checks (decision chains, feedback attribution and decisions, ideas, venue notes, and result records with stale inputs, in Chinese and English), the research code folder and its separate environment, and recorded runs with failures, missing outputs, and refused inputs. `test_ingest.py` also covers research feedback events, whose Word comments keep their authors.
- `test_complete_path.py` runs the scripts in sequence on a copy of the template's records with synthetic, labeled material, from an imported and cited source through an idea, a plan, a recorded result, the manuscript, an audit record, a build and release (where Pandoc is installed), an answered review round, and an applied revision to a saved version and the status summary, then a revision made in place that stays open until it is completed. It tests the deterministic layer only.
- `test_status.py` covers stage recognition for a new workspace and for a drafted paper with open review items and feedback, and revisions that are reported as open until they are completed or abandoned.
- `test_manuscript.py` covers the manuscript checks (a conforming manuscript in Chinese and English, every convention break, manifest problems and unlisted drafts, warnings and open markers), section lists, assembly, stale check records, and revisions: a conflicting author edit, reconciliation, an interrupted application resumed, restoring the baseline, and closing a revision as completed (in place or after a candidate, with what was still open) or abandoned. Where Pandoc is installed, it also adopts a Word manuscript (Chinese text, footnote, formulas, image, table), stops on tracked changes until they are accepted or rejected, brings a LaTeX file into workspace syntax, and keeps the Pandoc route to the researcher's manuscript.
- `test_export.py` covers the Word reference-document builder (settings and the schema order of section properties), the formula-by-formula equation check, releases (frozen once, refused when failed, stale, or with open markers), and, where Pandoc and pandoc-crossref are installed, real builds with layout expectations, anonymization, the title, authors, and keywords of `manuscript/metadata.yaml` reaching the Word file (also without a manifest line), refusal of a manuscript with problems, and a Mermaid diagram as a numbered figure.
- `test_review.py` covers the response and change records of a review round (including a change recorded only in a revision's own `changes.md`, which the check reports with the remedy), and reconciling a coauthor's Word file: tracked changes located in the manuscript, a conflicting later edit, a separate base file, and comments with their authors.
- `test_versions.py` covers the Git operations in disposable repositories with an empty global Git configuration: inspection of inherited template history, distinguishing a public environment-variable name from an actual credential, byte-preserving saves and clones under different line-ending settings, scoped saves, refused secrets and oversized files, comparisons with renames, retrieval and restore with the current content kept, the practice copy, the template's own `.gitignore` (what the scripts build for themselves stays out of saved versions, and the paper's files stay in), and backups to a local bare repository, refused without a confirmed destination and reported as failed when the destination is unreachable.
- `test_literature.py` covers Sciverse privacy and scope gates, provider-specific search records, snippets versus metadata and content, local extraction locators, bibliography links, 429 handling, and resumable public-PDF retrieval against synthetic responses and a local HTTP fixture. `test_sciverse_extensions.py` covers metadata filters, sorting, cursor resumption and recovery, relation provenance, duplicate-version handling, bounded resources, opt-in Paper Schema materials, and scope checks with synthetic responses. Live endpoint observations are recorded separately in the implementation status.

The agent and the template maintainer run these tests after changing a script. Researchers do not need to run them.
